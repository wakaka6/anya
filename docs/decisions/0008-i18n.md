# 0008: Every user-facing string is translated, at the app layer

Accepted, 2026-10-30.

## Context

Anya is built for a community beyond one language. Text written into a library (an error message, a status word) cannot be translated without editing that library, and text sent on the wire forces every downstream app into the sender's language.

## Decision

- **One catalog.** `anya-i18n` holds every string Anya shows: `crates/i18n/locales/<tag>/<area>.json`, one file per area (`gui`, `tui`, `overlay`, `tray`, `doctor`, `cli`, `error`, `common`), keys prefixed by their area, `{name}` for placeholders. English and Simplified Chinese ship first; English is the fallback.
- **Complete or not built.** A test fails when a locale lacks a key English has, has one English lacks, or changes a key's placeholders.
- **Libraries below the app hold no user text.** They return codes and typed errors; their Display text is English and for logs. The app looks the code up in the catalog.
- **The wire carries codes, not words.** `session_end` carries an `ErrorCode` and the engine's untranslated `detail`; apps translate the code. Text that arrives with a manifest is a `Text`: one string, or one per BCP-47 tag, resolved to the closest language.
- **The language is a setting.** `[ui] language` is a tag or `system`; `system` reads `LC_ALL`, `LC_MESSAGES`, `LANG`, `LANGUAGE`, then macOS's preferred languages.
- **The settings page uses the same catalog**, loaded as JSON; its HTML and JS carry keys, not text.

## Consequences

- Adding a language is a directory of files, an entry in `LOCALES` and a match arm; the test lists what is missing.
- Built-in engines label their settings in English and Chinese inside their manifests, the same way a plugin does.
- README.md and README.en.md stay the two languages of the docs.
