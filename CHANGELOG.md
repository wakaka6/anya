# Changelog

User-visible changes, newest first.

## Unreleased

- The whisper.cpp engine can run its server itself (docs/decisions/0018). On the Engine page, "Who runs the server" switches between a `whisper-server` you run and one Anya starts on this computer when you dictate, listening on `127.0.0.1` only and stopped after 10 idle minutes. Pick a model from a list (`base`, `small`, `large-v3-turbo-q5_0`, `large-v3-turbo`, `large-v3`, with the one that suits the computer marked) and it downloads with progress, can be cancelled and resumed, and is used once its pinned hash matches; or name a model file of your own. Downloads come from Hugging Face or a mirror you set. Anya says where it found `whisper-server`, or how to install it.

- New built-in engine `whisper-cpp`: recognizes on this computer with a whisper.cpp `whisper-server` (default `http://127.0.0.1:8080`, the one setting), so the audio stays on it; hotwords become whisper's prompt. It is on the Engine page with the other built-in engines and can be turned off like them.
- Three plugins ship in `plugins/`: `spoken-punctuation`, which turns spoken “逗号”, “句号”, “换行” and the like into marks and hands those words to the engine as hotwords; `app-hotwords`, hotwords per app in front; and `daily-notes`, which appends every dictation to a Markdown note per day. `cargo xtask ci` runs their tests with Bun.
- Anya writes a log: to stderr with `--daemon`, as `--help` says, otherwise to `anya.log` in the state directory, rewritten at each start. `--verbose` adds Anya's debug lines; `RUST_LOG` overrides both. Nothing was logged before, so a plugin's console output, a plugin killed for not answering and a failed hook left no trace.
- A failed dictation is kept in the activity list with its reason (an engine plugin's own words beside it); it only showed in the tray panel until the next dictation.
- A plugin that writes to its console in a loop that never yields is now killed and restarted like a silent one; its output counted as an answer to Anya's ping.
- A failed hook is logged with its plugin and code, and at debug level with the plugin's own message.
- The enable prompt and the Plugins page say what a plugin provides before it has ever loaded, from what the registry said at install; a plugin never enabled showed nothing.
- A plugin package that names no entry, an entry outside the package or missing from it, or another plugin protocol is refused with the reason when Anya loads it.
- The plugin market tags only engines as streaming or whole recording, and an installed plugin that is off says it receives nothing, not that it hears no sound.
- The official plugins, `spoken-punctuation`, `app-hotwords` and `daily-notes`, are built into Anya (docs/decisions/0017). The plugin market lists them first with an “Official” tag, also when the registry is unreachable, and installs them from Anya itself with nothing downloaded; installing and enabling are still two steps. `anya plugin search` and `anya plugin install` do the same. An installed official plugin is updated with Anya: at start it becomes the version this Anya ships, on or off as you left it, and the activity list says which plugins changed. When the registry cannot be read, the market keeps the official plugins and says so in one line under them, with a Try again link that leaves the cards in place while it retries; community plugins that then arrive fade in. It used to show nothing.
- A plugin with a required setting left blank waits for it instead of failing on every dictation: its hooks are skipped, the Plugins page says “Needs settings” with the setting's name and opens its settings, and `anya plugin enable` and `anya plugin list` say the same. Its hooks run from the next dictation once it is set. Required fields in plugin and engine forms read “Required” instead of “Default”.
- Plugins can do more than add engines (docs/decisions/0016). Before a dictation opens, a context plugin can add hotwords and set the language for the app in front (its bundle id on macOS, its window class on X11). After the final text, transform plugins rewrite it in the order you set (`[plugins] order`), and the rewritten text is what gets pasted; action plugins get the same text beside the paste, each plugin's in the order you dictated, without ever holding the paste up. A failing or slow plugin is named in the activity list and its step is skipped; your words are never dropped. Hooks apply to your own dictation only, not to continuous transcription or paired apps, and subscribers still receive the engine's text.
- A plugin runs inline, in QuickJS inside Anya, where it cannot reach the network or the disk and every call is stopped at its time and memory budget; or in a Bun process of its own, which Anya pings every second and restarts after 3 seconds without an answer, so one stuck plugin no longer freezes the others (docs/decisions/0015). A plugin with only an inline part needs no Bun. Budgets have defaults and fixed ranges; set them in `[plugins.limits]` (every plugin, and `chain_ms` for the whole transform chain) or `[plugins.limits.<id>]`. Plugin settings live in `[plugins.settings.<id>]`.
- `community-hooks`, the built-in piece that runs every community plugin's hooks, can be turned off in `[plugins.builtin]` or with `anya plugin builtin off community-hooks`.
- The settings window's Plugins page shows what each plugin provides, whether it runs inline only, and what each part receives (audio, the app in front, everything dictated) before you install or enable it; it draws a dictation as a line from recording through recognition to the paste, with context, transform and action hooks branching off where they run, in their order, lets you reorder them, links an empty kind to the market, and draws each plugin's settings.
- The registry index lists what a release provides (`provides`) and whether it runs in Bun (`host`) instead of `kind`; Anya downloads Bun only for a plugin that runs in it.
- A plugin package names its Bun entry `anya.host` instead of `anya.engine`, since the entry will provide more than engines (docs/decisions/0015). Rename the field in your plugin's `package.json`; one with `anya.engine` no longer loads.
- The hotwords file has one place: `hotwords.txt` next to the config file, by default `~/.config/anya/hotwords.txt`. `[recognition] hotwords_file` is gone, along with the file chooser on the Engine page, which now shows the path with a copy button. Without the file, or when it cannot be read, the config's own hotwords are used alone; a file that is there but cannot be read is also noted in the activity log. Move a list you kept elsewhere to that path, and remove `hotwords_file` from your config, which no longer loads with it.
- The settings window shows the app icon and name at the top of the sidebar, and the Route page's map draws Anya as the app icon.
- Plugins can have an icon, shown in the Plugins list and the market instead of the lettered tile. A package names it in `anya.icon`: a file in the package or a `data:image/…` URI, PNG, JPEG, GIF, WebP, ICO or SVG, at most 1 MiB; never a URL, so showing it reaches no author's server. The registry keeps a release's icon beside its tarball and lists it with its hash (`icon`, `icon_integrity`), so the market shows it before install; Anya downloads it the first time, checks the hash and keeps it. The official plugins ship with theirs.
- The Engine page shows each engine's logo instead of the lettered tile: Doubao, Qwen Fun-ASR, OpenAI, whisper.cpp and Xiaomi MiMo ship with theirs (AuralWise publishes none and keeps the tile), and a plugin's engine shows its plugin's icon.

- New Route page in the settings window, right under Activity: a live map of where each open session's sound comes from (your microphone, system sound, a paired app by name), the engine it goes to, and where its text goes (pasted, the clipboard, the overlay, back to the paired app, subscribed apps that were sent it). Only what is in use right now is drawn, with audio and text moving along the lines; hovering a source lights its route alone. Under it, the latest 200 messages (start, audio per second, partial and final text, failures), kept in memory only, with filters; a final of your own dictation links to its line on the Activity page. The Activity page no longer has a live card, and each dictation line names the engine that recognized it.
- The tray panel shows what you are saying while you dictate; it always showed "Listening" with no words.
- The number of apps subscribed, shown on the Apps page, follows apps connecting and leaving; it stayed at the count from when Anya started.
- The terminal UI is laid out in panels, like lazygit: the status and the activity log on the left, the settings on the right (their groups open one at a time), and what the selected setting is for below. `1`, `2` and `3` choose the panel; `j`/`k` walk the settings, or scroll the log when it is chosen; `←`/`→` change group; `l` enlarges the log. Under 90 columns only the chosen panel shows.
- Anya tells you when a newer version is out. Once a day it reads the Homebrew tap's formula (a request that sends only `User-Agent: anya/<version>`; `[updates] check = false` or the settings switch turns it off) and the tray panel, the settings page and the terminal UI show the notice. A Homebrew install gets an Upgrade action that runs `brew upgrade anya`; restart Anya to use the new version. Other installs are only told (docs/decisions/0014).
- Anya is MIT licensed (`LICENSE`, docs/decisions/0006).
- A failed dictation no longer tells you to press R in the overlay, its preview and the terminal UI: no key did anything there. Retrying is the tray panel's Retry button.
- New agent skill `skills/anya-hotwords`: run on a loop (`/loop 10m /anya-hotwords ~/.config/anya/config.toml`), it compares what Anya typed with the message you then sent to your coding agent, learns the words you fix by hand and the terms of your current work, and keeps `[recognition] hotwords_file` up to date, so recognition fits you better the more you use it.
- Several recognition engines can be set up at once, and each use picks its own: `[recognition] dictation`, `continuous` and `remote` (dictation from paired apps) replace `[recognition] engine`. A session goes only to its use's engine; a failure is still shown, never retried elsewhere. The Engine page lists every engine with its settings inline and has a "who uses which" section; the terminal UI and `--doctor` follow.
- The settings window and tray panel use push buttons, icon buttons and rows with a chevron instead of blue text links.
- The settings window's sidebar is quieter and grouped: Transcription, Recognition and Output under small headings, thin single-colour icons, a grey selection, General at the foot. It folds to a rail of icons with the button at its top, and stays as you left it. Hotkeys are only recorded now; the "Type it" field is gone.
- The tray panel looks like a macOS menu bar extra: the system's menu material with rounded corners, as tall as what it shows, Control Center style toggles for dictation and continuous transcription, and a toolbar of icon buttons for All Activity, Settings and Quit. The last sentence is no longer listed twice, and a recent sentence copies when clicked.
- Built-in engines can be turned off, with a switch on the settings window's Engine page or with `anya plugin builtin` (`off <id>` / `on <id>`; `[plugins.builtin]` in the config file, picked up by a running Anya). An engine any use has chosen stays on. Built-in and community engines now start and stop on one plugin runtime (docs/decisions/0012).
- A damaged `plugins.json` is reported instead of being read as an empty list, so installing or enabling a plugin can no longer overwrite the list of what is installed. The previous list is kept as `plugins.json.bak`, and `anya plugin` and the running Anya no longer write it at the same time.
- Starting Anya while its tray app is already running opens the running app's settings instead of starting a second copy that answered every hotkey twice.
- The recording time in the statistics counts each dictation's audio; it stayed at zero.
- The overlay preview also works from the settings page in a browser (`--web`).

- Changing the hotwords (in the settings, in the config file or in `hotwords.txt`) now reconnects a continuous session that stays open, once, so it takes them. Before, only the next session saw the change. Anya checks every 2 seconds and reconnects once a change has held for a check, at most once every 30 seconds, so a burst of edits or a file caught half saved makes one reconnect.
- The average and latest speed, and the minutes in the usage totals, count the audio of each dictation; they stayed at zero.

- On macOS the overlay's text (the notch and the capsule) is drawn with font smoothing, as solid as the system's own text; it used to look thin and faint.

- New settings window and tray panel in the style of macOS System Settings: a sidebar with eight pages (Activity, Dictation, Continuous, Engine, Plugins, Overlay, Apps, General), grouped sections, a plugin market on its own page, changes saved the moment they are made, a live input-level meter, an overlay preview that shows the real overlay for a moment, and a tray panel that shows the last sentence, a failure with retry, or what is missing before Anya can start.

- New app icon: Anya Forger hearing a thought, in a light variant (sky-blue, a thought bubble) and a dark one (night purple, glow and star eyes). The settings page, the tray panel and, on Linux, the window and tray icons follow the system appearance and switch when it changes; the macOS menu bar keeps its monochrome icon.

- Anya runs end to end on macOS and Linux (Wayland, X11): the `anya` binary wires global hotkeys, microphone and system-sound capture, five engines (Doubao, DashScope, OpenAI-compatible, AuralWise, MiMo), paste and clipboard output, the recording overlay (the notch on macOS), the tray app with its settings window, the terminal UI, `--web`, `--doctor`, `--install`, `anya subscribe` and `anya replay`.
- Every user-facing string comes from one catalog in English and Simplified Chinese; the interface follows the system language or `[ui] language`.
- The config file is `~/.config/anya/config.toml`, saved atomically and readable by its owner only; an edit made outside Anya is picked up without a restart.
- A setting with a value an engine cannot use is reported as invalid, not as missing.
- The environment check (`--doctor`, and at every start) names what is missing and how to fix it; a failed required check stops startup.

- Anya is an ASR gateway: a paired app (a phone, a browser page, another computer) sends its own microphone audio and gets results from the engine the user chose, without its own vendor account. LAN sharing is off by default; turned on, Anya also listens over TLS on the local network, and every connection there needs a token from pairing (a six-digit code or QR code in the settings). Each paired app has scopes (`dictate`, `subscribe_continuous`, `subscribe_dictation`) the user can change or revoke.
- Protocol: `session_start` carries `streaming`, whether partial results arrive while audio is still being sent. Clients send `pair`, `dictation_start`, `dictation_stop`, `dictation_cancel` and binary PCM audio; Anya answers with `paired`, `dictation_accepted` and `refused`. Pinned in `crates/protocol/tests/client.rs`; `fixtures/gateway.jsonl` shows a remote dictation client's stream.

- Provider plugins use the shared Engine and Manifest contracts. The anya-plugins registry publishes reviewed, versioned packages; Anya refreshes its index without installing plugins automatically.
- Engine plugins run in one Bun process that restarts by itself if it dies; a plugin that fails ends its session with an error and Anya never switches engines. Installing checks the package against the index's sha512 integrity, records it disabled, and enabling is a separate step. Bun is taken from PATH or, at the first install, downloaded at a pinned version and checked against its SHA-256. docs/plugins.md is the plugin author's guide, with the `@wakaka6/anya-plugin` SDK, the index format and the anya-plugins release workflow.

- Continuous transcription now defaults to Anya's built-in system-sound capture; dictation still defaults to the microphone. The audio layer also exposes loopback devices without requiring a virtual audio driver.

- Protocol 0: subscriber frames `hello`, `source`, `session_start`, `result` and `session_end`, and the engine `Manifest`. Version 0 may still change without notice.
- docs/protocol.md is the guide for apps that subscribe: the frames, ten ordering promises (a definite utterance never changes, a late subscriber catches up from the latest result…), how to read results for captions, notes and final text, and the compatibility rule. `crates/protocol/fixtures/` holds streams to test against, including `future.jsonl` with what a newer Anya may add.
- The Rust protocol types read frame types, sources, states and end reasons a newer Anya adds as `Unknown` instead of failing on the whole frame.
- A `level` frame carries each audio chunk's loudness for level meters, and `session_end` with reason `error` carries a `detail` to show the user.
